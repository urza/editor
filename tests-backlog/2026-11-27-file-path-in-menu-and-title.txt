Change: A note that is a file on disk has "Copy full path" and "Open location" in its row menu in the desktop shell, and the window title of the shell shows the full path after the note name.
Preconditions: The desktop shell, in a build that has the "Open location" command. One file on disk, for example C:\notes\todo.md, opened in the app with File > Open. One note that is not a file.
User Flow: Select the file note. Read the window title. Open the row menu of the file note. Select "Copy full path" and paste into the editor of the other note. Open the row menu again and select "Open location". Then open the row menu of the note that is not a file.
Expected Result: The window title is "todo.md (C:\notes\todo.md) - vrtti". The pasted text is C:\notes\todo.md, and the status bar said "path copied". The file manager of the system opens the folder C:\notes (Windows and macOS select todo.md). The menu of the note that is not a file has neither item, and its window title has no path.
Edge Cases: In a browser (Chrome or Edge, file opened with the file picker) the menu has neither item, and the title shows no full path. In a Space Window the title is "todo.md (C:\notes\todo.md) (<space>) - vrtti". When the file was deleted outside the app, "Open location" shows "cannot open the location" in the status bar.
